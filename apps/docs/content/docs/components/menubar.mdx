Menubars are composed, not shipped — like [Toolbar](/docs/components/toolbar), there is no `.ui-menubar` class or stylesheet. A utility container (`inline-flex items-center gap-px bg-card rounded-md shadow-sm p-xs`) holds a row of [Menu](/docs/components/menu) primitives. Each trigger carries `popovertarget` and `interestfor` pointing at its panel, so menus open on click or hover — and because only one `popover="auto"` can be open per stack, hovering an adjacent trigger closes the previous menu automatically: the classic menubar glide, with no JavaScript.

## Accessibility

The container deliberately does not claim `role="menubar"` — that role promises a single tab stop with roving arrow-key focus across triggers, which a static composition can't deliver. Every trigger stays natively tabbable, and each open menu has the arrow-key navigation the menu script provides. Give the container an `aria-label`.

## API

| Attribute                       | Target       | Values                              |
| ------------------------------- | ------------ | ----------------------------------- |
| (container)                     | any element  | Utility recipe — no component class |
| `popovertarget` + `interestfor` | Each trigger | Same panel id — click + hover glide |
