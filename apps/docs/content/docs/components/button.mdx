Buttons use the `.ui-button` class on `<button>` or `<a>` elements. Choose styles with `data-variant` and dimensions with `data-size`. Omitting `data-variant` applies the default style.

## With keyboard shortcuts

Add a `<kbd>` element inside the button for shortcut keys. Wrap a run of keys in a [`<ui-kbd-group>`](/docs/components/kbd) so their spacing stays consistent:

```html
<button class="ui-button">
  Search
  <ui-kbd-group><kbd>⌘</kbd><kbd>K</kbd></ui-kbd-group>
</button>
```

## API

| Attribute      | Values                                                              |
| -------------- | ------------------------------------------------------------------- |
| `data-variant` | `primary`, `muted`, `ghost`, `destructive`, `link` (omit = default) |
| `data-size`    | `sm`, `icon`, `icon-sm`                                             |

Customize buttons globally by overriding `--ui-button-background`, `--ui-button-radius`, `--ui-button-block-size`, etc. on `:root`.

Button metrics (block-size, radius, padding, font-size, icon size, ring color, border width/style) default to the shared [`--ui-field-*` family](/docs/components/input), so a button sitting beside an input, select, or textarea stays visually consistent: retune a `--ui-field-*` token once and buttons follow; override the `--ui-button-*` token to diverge just the buttons. Colors stay independent — a button surface is not a field surface.
