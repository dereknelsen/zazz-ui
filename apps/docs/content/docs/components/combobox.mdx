---
title: Combobox
description: An input combined with a predefined list — a filterable relative of select.
---

A `<ui-combobox>` looks like a select and filters like an autocomplete, but can never submit free text: the form value lives in an authored hidden input (`data-slot="combobox-value"`), synced when an option is committed. Options match against their visible label and carry their machine value in `data-value`; the committed option wears `aria-selected` and the shared option checkmark. On blur, stray text reverts to the last committed label, and cleared text clears the selection. The chevron toggles the full unfiltered list.

Omit the `popover` attribute on the panel for the **inline variant**: the list renders in flow, always open — no floating surface, chevron, or dismissal — with filtering, highlight, and commit unchanged. Used inside surfaces that already float, like a [Menubar](/docs/components/menubar) help menu.

Without JavaScript this control is inert — where a no-JS fallback matters, use [Select](/docs/components/select) instead.

## API

| Attribute                  | Target                         | Values                                       |
| -------------------------- | ------------------------------ | -------------------------------------------- |
| `data-value`               | `[data-slot="combobox-item"]`  | Submitted value (label is the match text)    |
| `data-keywords`            | `[data-slot="combobox-item"]`  | Space-separated extra match targets          |
| `data-sort`                | Root                           | `score` — rank by match (default: DOM order) |
| `name` / `value`           | `[data-slot="combobox-value"]` | The hidden input the form submits            |
| `data-side` / `data-align` | `[data-slot="combobox-panel"]` | Placement (popover matrix)                   |
