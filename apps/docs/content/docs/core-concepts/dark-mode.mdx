---
title: Dark mode
description: Dark mode support via light-dark() role tokens, color-scheme meta tags, and the .dark class.
---

Zazz enables dark mode by default. `:root` declares `color-scheme: light dark`, and semantic role tokens resolve through `light-dark()`. Role-based styles adapt across themes without duplicated rules.

```html
<section class="bg-background text-foreground p-lg">
  <h2 class="text-h3">Works in both themes</h2>
  <p class="text-muted-foreground">Adapts automatically across light and dark modes.</p>
</section>
```

## How roles resolve

Each semantic role specifies values for light and dark modes:

```css
/* from _variables.css */
--background: light-dark(var(--white), var(--neutral-900));
--foreground: light-dark(var(--neutral-900), var(--white));
--muted-foreground: light-dark(var(--shade-600), var(--tint-600));
```

Use semantic roles (`--primary`, `--background`) to ensure theme compatibility. Use fixed scale steps (`--primary-600`) only when colors must remain static.

Each role is declared exactly once. To re-skin a role for both themes, override that single declaration with a new `light-dark()` pair — every mode (system preference, manual toggle, sectional themes) picks it up:

```css
:root {
  --primary: light-dark(oklch(0.45 0.2 270), oklch(0.6 0.16 270));
}
```

## Theme configuration modes

### 1. System preference (default)

Include the `<meta name="color-scheme" content="light dark">` tag in `<head>` so native elements match OS preferences before styles load.

### 2. Manual toggle with `.dark`

Add the `.dark` class (or `data-theme="dark"`) to `<html>` to pin dark mode:

```html
<html class="dark">
  ...
</html>
```

`.dark`/`.light` and `data-theme="dark"|"light"` are pure `color-scheme` pins — they re-declare no tokens. Every `light-dark()` role re-resolves under the pinned scheme automatically.

## Building a theme toggle

Use an inline script in `<head>` to read preferences from `localStorage` and pin the theme class before first render. Persist under the `theme` key — the same key the kit's [head snippet](/docs/getting-started/head) script reads — so both scripts see the same choice:

```html
<meta name="color-scheme" content="light dark" />
<script>
  {
    const choice = localStorage.getItem("theme");
    if (choice) {
      document.querySelector('meta[name="color-scheme"]').content = choice;
      document.documentElement.classList.toggle("dark", choice === "dark");
      document.documentElement.classList.toggle("light", choice === "light");
    }
  }
</script>
```

Pinning `.light` as well as `.dark` matters: a stored "light" choice must override a dark system preference, not just fall back to it.

## Section-level themes

The same pins work on any container, not just `<html>` — and they nest. A `.dark` section renders dark on a light page, and a `.light` island inside it re-lightens its subtree:

```html
<section class="dark bg-background text-foreground p-lg">
  <h2 class="text-h3">Dark section on a light page</h2>
  <aside class="light bg-background text-foreground p-md">
    Light island inside the dark section
  </aside>
</section>
```

Give a themed section its own background (`bg-background`) — the scope pins `color-scheme` and re-asserts the foreground color, but leaves backgrounds to the section.

For a subtree that should always be dark regardless of theme (such as a code block), set `color-scheme` directly:

```css
pre {
  color-scheme: dark;
}
```

## Browser support

`color-scheme` is Baseline widely available. `light-dark()` is Baseline 2024 (Chrome/Edge 123, Firefox 120, Safari 17.5).
