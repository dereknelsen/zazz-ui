title: layers.css
description: The cascade layer architecture that lets utility classes override components without specificity conflicts.
---

`_layers.css` defines the [cascade layer](https://developer.mozilla.org/en-US/docs/Web/CSS/@layer) order for the framework. Layer order determines rule precedence instead of selector specificity.

```css
@layer variables, reset, vendors, legacy, zazz, overrides;

@layer legacy {
  @layer imports, components, utilities, migrations;
}

@layer zazz {
  @layer components, plugins, utilities;
}
```

`index.css` imports `_layers.css` first to establish this ordering before rules are defined.

## Layer precedence

Later layers override earlier layers regardless of selector specificity:

```html
<!-- .ui-button sets background in @layer zazz.components.
     .bg-primary sets background in @layer zazz.utilities and overrides it cleanly. -->
<button class="ui-button bg-primary">Save</button>
```

## Layer definitions

Priority order runs from lowest to highest:

| Layer               | Purpose                                                    | File                                                                    |
| ------------------- | ---------------------------------------------------------- | ----------------------------------------------------------------------- |
| `variables`         | Design tokens on `:root`                                   | [`_variables.css`](/docs/foundation/variables) + component token blocks |
| `reset`             | Element baselines and control resets                       | [`_reset.css`](/docs/foundation/reset)                                  |
| `vendors`           | Third-party CSS that does not build on Zazz                | `@import … layer(vendors)`                                              |
| `legacy.imports`    | Whole pre-Zazz stylesheets, imported as-is                 | `@import … layer(legacy.imports)`                                       |
| `legacy.components` | Curated legacy component CSS                               | Your legacy CSS, split out                                              |
| `legacy.utilities`  | Curated legacy utility CSS                                 | Your legacy CSS, split out                                              |
| `legacy.migrations` | Temporary translation shims for legacy class migration     | Custom `migrations.css`                                                 |
| `zazz.components`   | Component rules                                            | `primitives/<name>/<name>.css`                                          |
| `zazz.plugins`      | Zazz-dependent extensions (new primitives, added variants) | Plugin stylesheets, `layer(zazz.plugins)`                               |
| `zazz.utilities`    | Atomic utility classes                                     | [`_utilities.css`](/docs/foundation/utilities)                          |
| `overrides`         | Your app's deliberate overrides of anything below          | Your app CSS                                                            |

Position encodes intent. `vendors` sits above `reset` (the reset must not clobber a library's widget styling) and below `legacy` (your legacy CSS historically overrode vendor defaults, and still does). All of `legacy` sits below `zazz`, so migrated markup always resolves to Zazz; when a migration finishes, delete the `legacy` imports and the whole layer disappears in one move. Inside `zazz`, `plugins` follows `components` so an extension can restyle the primitives it extends (a plugin variant like `.ui-button[data-variant="glow"]` must beat the base `.ui-button` background), and `utilities` comes last, guaranteeing utility overrides.

## Never import into a bare parent layer

Within a layer, rules that don't belong to any named sublayer form an **implicit final sublayer** that outranks all named ones — the same way unlayered CSS beats layered CSS. Two consequences:

- `@import "old-app.css" layer(legacy)` would beat `legacy.migrations`, silently disabling your own migration shims. Import whole files into `layer(legacy.imports)` instead.
- Plugin CSS in bare `layer(zazz)` would beat `zazz.utilities`. Plugins publish into `layer(zazz.plugins)`.

## Unlayered CSS

Rules declared outside of any `@layer` override all layered rules regardless of specificity:

```css
/* Unlayered rule overrides layered components and utilities */
.ui-button {
  border-radius: 0;
}
```

Prefer the built-in `overrides` layer — it beats every Zazz layer while staying structured, and it's already declared:

```css
@layer overrides {
  .ui-button {
    border-radius: 0;
  }
}
```

Unlayered CSS still outranks `overrides` (that's inherent to layering), so treat unlayered rules as the last-resort escape hatch, not the default.

## Legacy CSS integration

Import whole legacy stylesheets into `legacy.imports` — never bare `layer(legacy)` (see above):

```css
@import "./legacy-app.css" layer(legacy.imports);
```

Zazz component and utility styles override legacy styles where selectors overlap, and translation shims in `legacy.migrations` override all other legacy CSS.

## Plugins

CSS that builds on Zazz — new primitives or added variants for existing ones — belongs in `zazz.plugins`:

```css
@import "zazz-plugin-datagrid/index.css" layer(zazz.plugins);

/* or, in the plugin's own stylesheet */
@layer zazz.plugins {
  :where(.ui-button[data-variant="glow"]) {
    background: linear-gradient(in oklch, var(--primary), var(--tertiary));
  }
}
```

Plugins override component defaults but never utilities. Third-party CSS that does _not_ build on Zazz belongs in `vendors` instead.

## Browser support

Cascade layers are Baseline widely available across Chrome, Edge, Firefox, and Safari.
