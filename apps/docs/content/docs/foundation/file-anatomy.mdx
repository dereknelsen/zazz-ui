Stylesheets in `@zazzdesign/ui` follow consistent organization across base modules and components.

## Base files

Source files split into `base/` (core foundation) and `ui/` (co-located component stylesheets, scripts, and markup):

| File                    | Purpose                                                      | Documentation                                         |
| ----------------------- | ------------------------------------------------------------ | ----------------------------------------------------- |
| `_layers.css`           | Declares cascade layer order (loads first)                   | [Layers](/docs/foundation/layers)                     |
| `_variables.css`        | Global design tokens (colors, type, spacing, metrics)        | [Theme variables](/docs/foundation/variables)         |
| `_reset.css`            | Native element baselines and zero-specificity control resets | [Reset](/docs/foundation/reset)                       |
| `_typography.css`       | Type scale, `.prose`, and typography utilities               | [Typography](/docs/foundation/typography)             |
| `_view-transitions.css` | Cross-document and SPA view transitions                      | [View transitions](/docs/foundation/view-transitions) |
| `_utilities.css`        | Atomic utility classes                                       | [Utilities](/docs/foundation/utilities)               |
| `_layout.css`           | Container bands and layout grid utilities                    | [Layout](/docs/foundation/utilities/layout)           |

## Component file structure

Component stylesheets organize rules in top-to-bottom order:

| Step | Section                  | Layer                    | Condition                     |
| ---- | ------------------------ | ------------------------ | ----------------------------- |
| 1    | CSSDoc header            | None                     | Always                        |
| 2    | Component token hooks    | `@layer variables`       | When component exposes tokens |
| 3    | Native element baselines | `@layer reset`           | When restyling native UI      |
| 4    | Component rules          | `@layer zazz.components` | Core component rules          |
| 5    | Utility classes          | `@layer zazz.utilities`  | When shipping utilities       |

```css
/**
 * _button.css: Button (.button)
 *
 * @layer      variables, components
 * @requires   layers.css, _variables.css, _reset.css
 * @uses       color-mix(), oklch(from ...) (hover/active tints)
 * @tokens     --button-* (@layer variables)
 */
@layer variables {
  :root {
    --button-background: var(--card);
    --button-height: var(--step-8);
    --button-radius: var(--radius-md);
  }
}

@layer zazz.components {
  .button {
    background-color: var(--button-background);
    height: var(--button-height);
    border-radius: var(--button-radius);
  }
}
```

## CSSDoc header tags

| Tag           | Required | Description                                       |
| ------------- | -------- | ------------------------------------------------- |
| Summary       | Yes      | First line: `_file.css: Component (.selector)`    |
| `@layer`      | Yes      | Cascade layers used in the file                   |
| `@requires`   | Yes      | Dependency files (set to `none` for `layers.css`) |
| `@uses`       | Optional | Modern CSS features or APIs utilized              |
| `@tokens`     | Optional | Token namespace exposed                           |
| `@consumedby` | Optional | Dependent files                                   |
| `@see`        | Optional | External references                               |
| `@example`    | Optional | HTML usage example                                |

## Token naming conventions

- **Default token:** `--{component}-{property}` (e.g. `--button-background`, `--dialog-radius`).
- **State variation:** `--{component}-{property}--{state}` with double-dash (e.g. `--button-background--hover`, `--field-border--focus`).

## Selector conventions

- **Classes:** `.component` and `.component__part` (e.g. `.input-group__addon`).
- **Variants:** Data attributes (e.g. `[data-variant="primary"]`, `[data-size="sm"]`, `[data-side]`).
- **Zero specificity:** `:where()` on reset and utility selectors.
- **Logical properties:** `inline-size`, `block-size`, `padding-inline`, `margin-block`.
- **State exclusion:** `:not(:disabled)` over order-dependent overrides.
