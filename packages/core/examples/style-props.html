    • Style props

    Open values, inline

    A style prop is a custom property set in the style attribute and read by a zero-specificity rule in the utilities layer: style="--px: 8" is padding-inline of eight spacing steps, --px-md takes over from the md container width. Eight labelled cases below exercise the contract; the readout at the end prints the computed values and refreshes on resize.

    Case a

    Responsive padding on a div

    style="--px: 8; --px-md: 12". Padding-inline is eight steps below md and twelve at md and up. The base gate --px: never matches --px-md:, so the two rules stay independent and source order picks the wider one.

    --px: 8 · --px-md: 12
    Case b

    A prop beats a component's own padding

    The same --px: 8; --px-md: 12 on a .ui-button. The button sets its own padding-inline from --ui-button-padding in zazz.components; the prop rule lives in zazz.utilities, ordered after it, so the prop wins with no !important.

    Case c

    A child does not inherit the prop

    Every prop is registered inherits: false. The outer box sets --px: 8; the inner box sets nothing, so it reads an empty --px and keeps zero padding. Only the private coordination vars (--_gap, --_grid-cols) travel to children.

    child · no style attribute · padding-inline stays 0
    Case d

    --gap feeds the basis fractions

    A .flex .flex-wrap row with style="--gap: 4" and two .basis-1/2 children. --gap also sets --_gap, so each child's basis is (100% - gap) / 2 and the pair fills one line exactly, the same as with .gap-*.

    .basis-1/2
    .basis-1/2
    Case e

    --grid-cols without .grid

    style="--grid-cols: 3" on a plain div, no .grid class. The prop sets display: grid, three minmax(0, 1fr) tracks, and --_grid-cols so spans clamp to the track count.

    1
    2
    3
    Case f

    A raw length on --w

    style="--w: 16rem". Sizing props pass the value through unchanged to the logical property, here inline-size.

    --w: 16rem
    Case g

    A theme override and a prop, side by side

    A <style> block in this section sets :root { --ui-field-padding: var(--step-5) }, the global theme lever for every field-derived control. The plain button picks the new default up through the token chain (every button on the page does); the button carrying --px: 8; --px-md: 12 still shows the prop, because the utilities layer wins over the component rule that reads the token. The override must sit on :root: --ui-button-padding reads --ui-field-padding at :root, so a value set lower in the tree never reaches it.

    Case h

    --mx: auto has no effect

    Spacing props multiply by --spacing-interval, so --mx: auto makes the calc() invalid at computed-value time and margin-inline falls back to zero: the first box hugs the start edge. Auto margins are a finite value, so they stay a class: the second box uses .mx-auto and centers.

    --mx: auto · not centered
    .mx-auto · centered
    Readout

    Computed values

    One line per case from getComputedStyle, refreshed on resize. The first line reports the width of the size container the flags read from.
